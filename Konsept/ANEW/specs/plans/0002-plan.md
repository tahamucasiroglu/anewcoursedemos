## Risks & open questions
1. **docs "ASP.NET Core Identity" diyor.** Öneri: Identity'nin yalnızca `PasswordHasher<T>`'ini kullan; `UserManager`'ın kilit sayacı
   oku-değiştir-yaz (AC-6'yı eşzamanlılık istisnasıyla çözer, sayacı atomik saymaz) ve 7 tablo getirir; Identity sonra kilitte sayacı da farklı
   sıfırlar (AC-7). Gerekçe: vetted hash + kendi atomik kuralımız; docs/security.md'ye "Identity hasher" diye netleştirme yazılır.
2. **Refresh ucu Req 11 listesinde yok.** Öneri: `api/auth/refresh` `[AllowAnonymous]` ama yalnızca geçerli refresh token (kimlik bilgisi)
   ile çalışır, başka veri dönmez; "giriş" istisnasının parçası sayılır ve AC-11 izin listesi testinde açıkça yer alır. Alternatif (önerilmez):
   uzun ömürlü JWT — anında iptali yine DB'ye bağlar, docs'tan sapar.
3. **AC-6 atomikliği.** Yanlış şifre tek ifade: `UPDATE identity.users SET failed_login_count = CASE WHEN failed_login_count+1>=3 THEN 0
   ELSE failed_login_count+1 END, locked_until = CASE WHEN failed_login_count+1>=3 THEN @now+15dk ELSE locked_until END WHERE id=@id AND
   (locked_until IS NULL OR locked_until<=@now) RETURNING failed_login_count, locked_until`; 0 satır → kilitli (kilit mesajı, değişiklik yok,
   AC-7). Başarı da kilit koşullu tek `UPDATE` (sayaç 0, `last_login_at`). Satır kilidi sıralar; kilit sonrası sayaç 0 → "2 hakkınız kaldı".
4. **Eşzamanlı refresh (sayfa + 3 sn yoklama aynı anda).** Öneri: Web'de eski refresh hash'i başına `SemaphoreSlim` + 60 sn `IMemoryCache`
   (aynı yeni çift paylaşılır); Api'de dönüş atomik `UPDATE … WHERE refresh_token_hash=@old AND revoked_at IS NULL AND last_used_at>@now-14g`.
   Eski token yeniden gelirse yalnızca 401 + Warning (tüm oturumları iptal etmek LAN'da yanlış alarmla kullanıcıyı atar). Web tek süreç (Pi).
5. **Rate limit nerede.** Öneri: **yalnızca Api** (asıl karar Api'de; 8001'e doğrudan istek de sınırlanır). Api Web'in IP'sini gördüğünden
   Web, login/register çağrısına `X-Konsept-Client-Ip` ekler; Api bu başlığa **yalnızca geçerli servis anahtarıyla** güvenir. ASP.NET Core
   `AddRateLimiter` + `TimeProvider`'lı `FixedBlockRateLimiter` (IP başına 60 sn'de 10; 11.'de 60 sn blok; kuyruk 0) — FakeTimeProvider ile
   test edilebilir. 429 ProblemDetails `auth.too_many_attempts`; servis katmanına ulaşmadığı için hak sayacı değişmez.
6. **Kayan süre ve yoklama.** Oturum her doğrulamada en fazla dakikada bir `last_used_at` günceller; açık sekmenin 3 sn yoklaması da
   "kullanım" sayılır. Öneri: kabul (Req 16 için de doğal: açık sekme varken oturum yaşar). JWT ömrü `TokenValidationParameters.
   LifetimeValidator` ile aynı `TimeProvider`'dan doğrulanır (FakeTimeProvider testleri gerçek saatle çelişmesin).
7. **Kullanıcısız olaylar (ajan, 0012'ye kadar ortak).** Req 18 "yalnızca kendi olayları". Öneri: şerit = kendi olayları + `UserId` boş
   sistem/ajan olayları; başka kullanıcının olayı asla. Aksi halde 0001 `AgentEvents_Persisted_LastEventShownInStrip` (korumalı) kırılır.
   Kayıtlı olmayan e-posta denemesi hiç olay yazmaz (boş kullanıcılı bile değil). 0012 ajan olaylarını sahibine bağlar.
8. **Mevcut testler default-deny'de kırılır.** Öneri: assert'e dokunmadan kurulumu değiştir — Web'de substitute API'ye varsayılan oturum ve
   gerçek `/giris` akışıyla giriş, Api'de gerçek register+login uçlarıyla Bearer. Anonim davranış yeni testlerde ayrıca kanıtlanır.
9. **Yeni paket:** `Microsoft.AspNetCore.Authentication.JwtBearer` 10.0.15 (MIT, aktif, transitive `Microsoft.IdentityModel.*` merkezi
