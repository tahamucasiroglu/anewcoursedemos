## Cevap

### Son mesajdan beri yapılanlar
Spec yazıldı: `specs/active/0003-raspberry-pi-kurulumu.md` (Draft). Verdiğin kararlar spec'e işlendi:
- Pi'deki PostgreSQL 17 kullanılacak.
- Web nginx ile ayrı birim olarak sunulacak (`http://192.168.1.102:8080`); API ayrı servis olacak.

**Hassas alan:** S3 = kimlik/gizli bilgi (veritabanı şifresi, kısıtlı veritabanı kullanıcısı). Bu yüzden:
- her düzeltme turundan sonra yeniden bağımsız inceleme yapılacak;
- bu alandaki kriterler (AC-4, AC-5) başka bir spec'e ertelenemeyecek;
- VERIFY'da her biri kasıtlı bozmayla kanıtlanacak.

### Spec özeti — 12 kabul kriteri
| Kriter | Ne kanıtlanacak |
|---|---|
| AC-1 | `http://192.168.1.102:8080` açılınca "Sistem çalışıyor" görünür (gerçek API + Pi PostgreSQL 17); sayfa yenilenince de açılır |
| AC-2 | API dışarıya kapalı; yalnızca 8080 üzerinden (nginx) çalışır |
| AC-3 | API root olmayan ayrı bir kullanıcıyla çalışır; Pi yeniden başlatılınca ve API çökünce kendiliğinden kalkar |
| AC-4 | Veritabanı kullanıcısı yalnızca kendi veritabanına bağlanır; süper kullanıcı değildir; veritabanı ve rol açamaz; migration uygulayabilir |
| AC-5 | Şifre yalnızca root'un okuyabildiği dosyada durur; repoda, komut çıktılarında ve loglarda geçmez |
| AC-6 | Dağıtım tek komut; sonunda "çalışıyor" doğrulanır; Pi'de en fazla 2 sürüm tutulur |
| AC-7 | Kontrol başarısızsa otomatik olarak önceki sürüme dönülür; elle geri dönme komutu da var |
| AC-8 | Yalnızca web güncellenince API yeniden başlamaz; yalnızca API güncellenince web değişmez |
| AC-9 | Loglar `/var/log/okul` altında tutulur, 30 gün saklanır (backlog B-9 kapanır) |
| AC-10 | Telefondaki mobil uygulama, Pi adresiyle "Sistem çalışıyor" gösterir |
| AC-11 | Kaldırma komutu onaysız hiçbir şey silmez; onaylanınca yalnızca bizimkileri siler, diğer uygulamalar çalışmaya devam eder |
| AC-12 | Kurulum ve dağıtım ikinci kez çalıştırılınca hata vermez, veriyi ve şifreyi bozmaz; diğer portlar ve uygulamalar aynı kalır |

12 kriter, ANEW'in ~10 sınırının biraz üstünde. Hepsi tek bir yeteneğin (deneme ortamına kurulum) güvenlik ve geri dönüş sınırları olduğu için bölmeden tek spec öneriyorum.

### Öz eleştiri ("bu spec'i okuyan geliştirici neyi hâlâ sorar?")
| # | Boşluk | Önerim |
|---|---|---|
| Ö-1 | **Pi'nin IP'si değişirse** (modem yeni adres verirse) web ve mobil yanlış adrese gider. | **Ekle:** Pi adresi tek ayardan gelsin (SSH tanımı `tmpi` + ayar dosyası). Belgeye "modemde Pi'ye sabit IP ver" önerisi yazılsın. Web aynı adresten çalıştığı için etkilenmez; yalnızca mobil ayarı değişir. |
| Ö-2 | **Geri alma ve veritabanı:** Yeni sürüm bir migration içeriyorsa, eski sürüm yeni şemayla uyumsuz olabilir. | **Ekle (kısıt):** Geri alma yalnızca kodu değiştirir, şema ileri yönlüdür. Migration içeren bir sürümden geri dönülürken komut uyarı versin. |
| Ö-3 | **Aynı anda iki dağıtım** çalışırsa sürümler karışabilir. | **Ekle:** Dağıtım, başka bir dağıtım sürüyorsa çalışmayı reddetsin (kilit). |
| Ö-4 | **Dağıtım sırasında kısa kesinti** olur: API yeniden başlarken birkaç saniye. | **Kabul:** Deneme ortamı için sorun değil; spec'e not düşülsün. |
| Ö-5 | **SD kart doluluğu:** sürüm başına ~100 MB × 2 sürüm, artı loglar (30 gün, dosya başına en çok 100 MB). | **Kabul:** 101 GB boş alan var; kurulum, 1 GB'tan az boş alan varsa durup uyarsın. |
