**Konu 10/12 — Git kuralları** (`docs/git.md`)

Durum: Repo yerel (`git init`, dal `main`). **Remote (GitHub) yok, CI yok, henüz commit yok.**

ANEW'in varsayılan kuralları güvenli. Önerim bunları aynen tutmak ve birkaç proje kararı eklemek:

**ANEW varsayılanları (aynen):**
- Dallar: `feature/<spec-no>-<kisa-ad>`, `fix/<rapor>-<kisa-ad>`, `refactor/...`, `trivial/...`, bootstrap için `chore/bootstrap`. **Spec yoksa dal da yok.**
- Commit mesajları: Conventional Commits + plan referansı, ör. `feat(attendance): bulk mark endpoint [plan 0003/2]`.
- `main` dalına doğrudan commit **yasak**. Force push ve geçmiş yeniden yazma **yasak**; geri alma `git revert` ile yapılır.
- Commit yalnızca adı verilen dosyalarla yapılır (`git commit -- <yollar>`); `git add .` / `-A` kullanılmaz.
- Commit'i yalnızca `scripts/check`'in kendi çıkış kodu belirler (yeşil değilse commit yok).
- Ajan commit mesajını kendisi yazar. Onaylanan plan, o planın `[plan NNNN/n]` commit'lerini kapsar; her commit için ayrı onay istenmez.

**Proje kararları (önerim):**
1. **Commit mesajı dili: İngilizce** (Konu 6'da onaylandı). Gövdede gerekirse Türkçe açıklama olabilir.
2. **Birleştirme (merge), remote olmadığı sürece:** SHIP onayından sonra yerelde `git merge --no-ff <dal>` ile `main`'e. Remote/GitHub eklendiğinde PR + squash-merge'e geçilir. (Remote/CI sorusu RAPOR adımında ayrıca sorulacak.)
3. **Push:** Yalnızca sen açıkça istediğinde. Ajan kendiliğinden push yapmaz.
4. **Promtlar kayıtları:** Her istek+cevap dosyası, o anda üzerinde çalışılan dala ayrı bir commit olarak girer: `docs(promtlar): 0016 <konu>`. Bu commit'ler yalnızca `Promtlar/` dosyalarına dokunduğu için ek onay istemez.
5. **Kapsam dokümanı** (`okul-yonetim-platformu-kapsam.md`) repoda kalır ve değiştirilmez. Kapsam değişikliği gerekirse yeni bir ADR veya spec ile yapılır.

**Commit kimliği:** Git kullanıcı adın `tahamucasiroglu`. Ajan commit'lerinin sonuna `Co-Authored-By: Claude` satırı eklenir.

**Dokümanda istenen:** Doküman git veya sürüm kontrolü hakkında bir şey söylemiyor. Bu konu tamamen süreç kararı. Dokümanın "Her aşama, önündeki kapının kriteri sağlanmadan başlamaz" ilkesi, ANEW'in "spec yoksa dal yok" kuralıyla aynı ruhta.
